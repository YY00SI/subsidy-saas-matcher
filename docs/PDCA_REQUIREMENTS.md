# PDCA Requirements

`subsidy-saas-matcher` の収益化PDCAに必要な情報です。パスワードは保存しない。

## 必要サイト

| 用途 | サイト | 必要情報 |
| --- | --- | --- |
| 成果確認 | A8.net | ログイン可否、案件別クリック、発生成果、確定成果、EPC、承認率 |
| 公開管理 | GitHub | リポジトリ、GitHub Pages、Actionsログ、デプロイURL |
| 検索流入 | Google Search Console | クエリ、ページ、クリック、表示、CTR、平均掲載順位、インデックス状況 |
| 行動分析 | GA4 | PV、参照元、滞在、CTAクリック |
| 補助金データ | JGrants | API更新可否、取得件数、受付中件数 |
| 追加案件 | A8.net / ASP各社 | 提携状態、成果条件、広告素材、否認条件 |

## ID/PW管理

- A8.netとGitHubのID/PWはユーザー提供済みだが、このリポジトリには保存しない。
- パスワードは最終回答、ドキュメント、ログ、`.env` に書かない。
- IDも原則としてドキュメントには残さず、PDCA実行時にユーザーまたはブラウザの保存情報から利用する。
- GitHubの公開ユーザー名や公開URLは、公開情報として必要な場合のみ扱う。

## 改善判断

- GSC表示0: インデックス、内部リンク、サイトマップ、記事テーマを見直す。
- 表示ありクリック0: タイトル・メタ・H1を検索意図に寄せる。
- クリックありA8クリック0: CTAの位置、文言、導線を見直す。
- A8クリックあり成果0: 案件のLP一致、成果条件、訴求タイミングを見直す。
- 成果あり: 同じ悩みの周辺ページを追加し、内部リンクを増やす。

## 追加ASP候補

現時点ではA8.net中心で運用する。成果が出たら、以下を比較対象にする。

- もしもアフィリエイト
- バリューコマース
- アクセストレード
- afb

追加判断の条件:

- 会計・請求書・法人カード・ファクタリング・バーチャルオフィス案件がある
- 成果条件が明確
- 承認率またはEPCが確認できる
- 広告主LPが補助金文脈と矛盾しない

## 次に不足している情報

- A8.netの直近30日レポート
- A8.netの提携済み案件一覧と成果条件
- GSCの現在値
- GA4導入有無
- GitHub Pagesの直近デプロイ状態
- 公開サイトのインデックス状況
