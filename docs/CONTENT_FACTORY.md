# Content Factory

`subsidy-saas-matcher` を軽量モデルでも継続拡充できるようにする手順書です。

## 目的

- 補助金情報だけでなく、申込意図が強い悩み別ページを増やす。
- A8.net等のアフィリエイト案件を、読者の課題と補助金のタイミングに合わせて配置する。
- ランタイムでLLMを呼ばず、静的ビルドで完結させる。

## 拡充すべきページ種別

優先順位は以下。

1. 資金繰り系: 補助金後払い、入金待ち、立替資金、ファクタリング
2. 創業準備系: 法人口座、登記住所、請求書、会計管理
3. インボイス・電帳法系: 請求書、電子契約、文書管理
4. 業種別DX: 建設、飲食、小売、美容、医療、運輸、製造
5. SaaS比較: freee、マネーフォワード、弥生、Misoca等

## 1ページの必須構成

- 検索意図に直結するH1
- 読者の失敗リスク
- 補助金の使いどころ
- 導入すべきSaaSまたはサービス
- 公式確認を促す注意
- アフィリエイトリンク
- 内部リンク

## 表現ルール

- 「必ず採択される」「確実に補助される」は禁止。
- 補助金の金額・補助率は変わるため、公式サイト確認を必ず促す。
- A8案件は広告であることがわかる文脈で配置する。
- 申請代行、税務、法務に踏み込む場合は、専門家確認を促す。
- 補助金は後払いであることを資金繰り導線に自然につなげる。

## アフィリエイト配置

配置先:

- ヘッダー近くの一次CTA
- 本文中の課題解決ブロック
- 記事末尾の比較CTA
- 固定フッターCTA

リンク要件:

- `target="_blank"`
- `rel="sponsored noopener noreferrer"`
- `utm_source`
- `utm_medium`
- `utm_content`

## データ更新

補助金データを更新する場合:

```powershell
npm run update:all
npm run test
npm run build
```

JGrants APIやネットワークが失敗した場合は、`data/raw/fallback-subsidies.json` と既存キャッシュでビルド可能にする。

## 新規案件追加

1. A8.netで案件を確認する。
2. 提携状態、成果条件、否認条件、広告主名、LP URLを確認する。
3. `data/tools.json` に追加する。
4. `use_cases` と `category` を `data/taxonomy.json` に合わせる。
5. `priority_score` を高単価・高CVの案件ほど高くする。
6. `npm run build` でツール詳細ページが生成されることを確認する。

## 公開前チェック

- テスト: `npm run test`
- ビルド: `npm run build`
- 生成ページ数が増えていること
- アフィリエイトリンクに `rel="sponsored noopener noreferrer"` があること
- パスワード、ログイン情報、APIキーをファイルへ書いていないこと

## 追加済みの高意図ページ

- `/needs/cashflow/`: 補助金後払い・資金ショート対策
- `/needs/startup/`: 創業直後の口座・住所・請求書準備
